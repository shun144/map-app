# 保存は利用者が保存ボタンを押したときだけ行う

操作中のビューポートは地図だけ、レイヤー構成は TanStack Query のキャッシュだけで持ち、IndexedDB へは保存ボタンを押したときにまとめて書く。利用者が「残したい状態」を自分で決められるようにするため。

当初は操作のたびに自動保存していた（ビューポートは移動終了の 300ms 後、レイヤー構成は即時）。自動保存では、試しに切り替えた表示もそのまま次回起動時に復元されてしまう。

## Consequences

- 保存せずにリロードすると、最後に保存した状態に戻る。画面には最後に保存した時刻を表示し、未保存の変更が消えることを利用者に気づかせる。
- ビューポートとレイヤー構成は1つのレコードにまとめ、1回の書き込みで保存する。別々に書くと片方だけ成功する可能性があり、片方だけが新しい組み合わせで復元されてしまうため。
- 保存対象のうち、ビューポートは押した時点の地図から、レイヤー構成はキャッシュから読む。それぞれの正の持ち主から読むため（ADR 0001）。
- 書き込みが保存ボタンの1か所に集まったので、レイヤー操作の楽観的更新と失敗時の巻き戻しは不要になった。
