# 操作中のビューポートは地図インスタンスを正とする

ドラッグ・ズーム中のビューポートは地図インスタンスだけが持ち、地図を動かしても TanStack Query のキャッシュは書き換えない。いまのビューポートが必要な処理（保存ボタンなど）は、その時点で MapController から読む。キャッシュから地図への反映は、初期表示と明示的な移動操作（「保存した位置に戻る」など）に限る。

キャッシュを正とする制御コンポーネント方式も検討したが、毎フレーム React の再レンダリングが発生し、地図→キャッシュ→地図の更新ループも起こりやすいため採用しなかった。移動終了ごとにキャッシュへ書き換える方式も一時期採ったが、読む側が保存ボタンだけで、押した瞬間に地図から読めば足りるためやめた。

## Consequences

- キャッシュ上のビューポートは「最後に読み込んだか保存した値」であり、いま見ている位置とは一致しない。
- キャッシュの更新を地図へ反映する購読は作らない。反映すると自分が書いた値で地図を動かすループになる。
- レイヤー（ベースレイヤー・オーバーレイヤー表示設定）は逆向きで、キャッシュを正とし、変化を差分で MapController に反映する。レイヤーは React の UI からしか変わらないため。同期の向きがビューポートと非対称なのは意図的である。
- レイヤーの変化は QueryCache を直接購読して受け取る。再描画と useEffect の依存配列を経由する方式は、操作から地図の更新までのつながりを追いにくいためやめた。書き込む関数の中で地図にも反映する方式は、その関数を通らないキャッシュの変更（再取得など）が地図に届かないため採らなかった。
